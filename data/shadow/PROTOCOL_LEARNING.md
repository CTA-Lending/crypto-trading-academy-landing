## 白話版(給第一次看的人)
同一個 AI、同一天、看同一份行情、守同一套規則,**分成兩個分身**。兩個分身都看得到自己目前的持倉與最近 5 天損益(跟主實驗一樣),差別只有一個:
- **有筆記的分身**:每 7 天看一次**程式算好的自己成績單**,寫下最多 2 條筆記;之後每天做決定時看得到這些筆記。
- **沒筆記的分身**:沒有任何筆記。

名字只說明它多做了什麼,**不代表它會變好** —— 外部研究裡,加了記憶反而變差的例子不少。
三家 AI(GPT、Gemini、Claude)各有一對分身,共 6 位;每位 $10,000 模擬金,零真錢。

要回答的問題:**同一天、同一個狀態下,讓 AI 看自己寫的筆記再做決定,隔天的模擬報酬會不會不一樣?**
怎麼量:有筆記的分身當天看得到筆記時,6 位的正式決定都做完之後,程式用它當天的題目**重問兩次**:一次帶著筆記、一次把筆記拿掉(哪一次先問,事先排好、逐日輪換)。
兩個答案從**同一個起點**各自算到隔天,差多少,就是「筆記讓當天那個決定差了多少」。
這樣量不會被「兩個分身持倉越走越不一樣」的運氣干擾 —— 附錄 E 的模擬顯示,筆記明明沒作用時,
直接比兩個分身整段期間的報酬,在大趨勢的行情裡有約 **2 成**機會被誤判成「有差」;同一起點的比法在所有模擬情境都接近應有的 5%。
這個比法回答的是「**當天**帶不帶筆記,決定差多少」;它**不回答**「整年下來淨值會不會比較高」。
兩個分身整段期間的報酬差照樣每天公開,作為次要指標(它的 p 值沒有校準,只供參考)。
**只在第 365 天做一次正式判定**,之前只公開描述數字。三種可能的結論,開跑前就寫好了(§6.5)。

## 1. 實驗問題(雙尾)
> **主要**:在相同模型、相同行情快照、相同規則與成本下,**在有筆記分身已經走出來的持倉狀態下**,同一個決策日,
> LLM 看到「**自己根據已結算成績寫的筆記**」時做出的配置,與同一個提示詞**只拿掉筆記**時做出的配置,
> **隔日**扣除模擬成本後的報酬是否不同?方向照實公開。這是**當天筆記區塊的單日對比**。
>
> **關鍵次要(政策層次,探索性)**:有筆記的分身與沒筆記的分身,處理期每日報酬是否不同?

主要問題量的是「**當天看到這些筆記**」對當天決定的影響;筆記對持倉、財富與之後決定的**間接、累積影響**不在主要問題裡,
只反映在次要的報酬差。**主要結果顯著,不等於整年的淨值比較高。**
**沒有安慰劑筆記對照**(例如別段期間或打亂的成績單),所以結果不能解讀為「學習能力」,只能解讀為「看到這種筆記」的效果(§12)。

## 3. 兩個分身的差別(唯一)
- 兩個分身的決策提示詞由**同一個函式**產生:系統提示、提示詞模板、候選表(同一份行情快照)、規則、結尾**逐字相同**。
- 「你的現況」一段填**各自的**權益、持倉與最近 5 日損益。第 1 日兩者完全相同;之後兩個分身決定不同,這一段自然不同 —— 這是被量測的結果的一部分,不是額外給的資訊。
- 有筆記的分身在「你的現況」之後多一段筆記區塊(格式見附錄 A);**0 條時整段不出現**。
- 同狀態比較(§4.5)的兩次重問:「帶筆記」= 有筆記分身當天的正式提示詞**逐字相同**;「拿掉筆記」= 同一提示詞**只少筆記區塊**
  (程式每次執行時比對,測試逐字釘住)。
- 決策呼叫一律不帶對話歷史;反思的原始輸出**不得**以任何形式進入決策呼叫,唯一通道是筆記的 `text`(`evidence` 不顯示在決策提示中,測試釘住)。
- **任何送給 AI 的內容都不含日期**(決策提示、成績單、筆記只用「第 N 日」),避免只有一邊知道「今天大約幾號」。
- 兩個分身都看不到:排行榜、另一個分身的成績、主實驗任何受試者的成績。
- 每天記錄每一位的系統提示雜湊、候選表雜湊、「你的現況」雜湊、筆記區塊雜湊、完整提示雜湊;同一天 6 位的系統提示與候選表雜湊必須相同,不同就在公開資料上標示。

## 4. 學習機制(唯一,凍結;模板全文與規則程式的雜湊在附錄 A,程式執行時比對,不符就拒跑)

### 4.1 時點與一天的順序
- 第 **7、14、21…** 個決策日,**當日換倉完成並記帳之後**反思;成績單用**含當日在內的最近 7 個已完成決策日**。
- 筆記從**下一個決策日**起才看得到 → 第 1~7 日的決策都沒有筆記。
- 一天的順序唯一:
  ① 抓行情(同一份快照給 6 位;同狀態比較**單獨持有**、今天不在幣海的幣另外抓價與資金費,**不進候選表**)
  → ② 結算昨天的持倉 → ③ 到期的筆記失效 → ④ 6 位正式決策 → ⑤ 同狀態比較的兩次重問(§4.5)
  → ⑥ 抓成交價、換倉、記帳;結算昨天的同狀態比較 → ⑦(反思日)反思。
- 反思當天沒做完(當機、斷電):下一次執行時**在任何決策之前**補做,帳本標 `late`;成績單與筆記建立日仍以反思日為準。已拿到的 AI 原文沿用、**不重抽**。
- `day_index` = 本組**實際執行**的決策日序號(缺失日不前進);筆記效期的 28 天是**日曆日**。計畫的 365 個決策日跑滿即停(程式拒絕第 366 日)。

### 4.2 成績單(程式算,LLM 不參與計算;只含該分身自己的帳)
1. 每個「第 N 日」:自己的日報酬、`bench_eqw_L` 日報酬、`bench_btc_L` 日報酬
2. 7 日合計(複利)
3. (背景)開跑以來累計:自己與 `bench_eqw_L`
4. 賺最多的 3 檔與賠最多的 3 檔(損益金額 = 價格變動 + 資金費;方向取自**產生這筆損益的實際持倉**,即前一次換倉後的部位,不是當天的意圖配置)
5. 換倉成本、換手金額、成本 ÷ 換手;全現金天數、平均總曝險、基建保護(只准減倉)天數
6. **三類分開**:你的輸出違規天數(超過曝險/非候選幣)、**系統沒拿到你的回覆**天數(供應商或我方問題,明寫「不是你的錯」)、輸出無法解析天數(可能被截斷)。分類與主實驗用同一支函式
7. 每條有效筆記:寫下之後(**不含寫下當天**)的同期複利報酬與 `bench_eqw_L`,並明寫「只是同時發生,不代表是這條筆記造成的」;寫下後還沒有完整日 → 寫「尚無完整日」

### 4.3 反思輸出、解析與「來源引用檢查」
- 只接受含 `new_notes` 的 JSON 物件;有多個時取**最後一個**;頂層欄位只能是 `new_notes`、`keep`、`retire`。不合 → **反思失敗**(不是「選擇不寫」),當期不新增、不續期、不退役,照常到期;記為基建事件,**不算違規**。
- `new_notes` 最多 **2** 條;`text` 去除換行後最多 **80 個字元**(Unicode 碼位);`text`、`evidence` 必須是文字。
- **來源引用檢查**:`evidence` 必須照抄成績單中「- 第 N 日:」那 7 行的日標籤(`第12日`、`第 12 日`、`D12` 都算),或「賺最多/賠最多」列出的幣種代號(`BTCUSDT`、`BTC/USDT` 都算 BTC;單一字元的代號也算)。
  **不算**:每日那幾行裡參考組的 BTC、筆記那一行的「第 N 日寫」、其他沒印在成績單上的日或幣。反思提示把這條規則原文告訴 AI(附錄 A.1)。
  ⚠️ 這**只檢查有沒有引用來源,不檢查筆記內容是否屬實**;對外一律稱「來源引用檢查」,不得稱「已驗證」。
- `keep`/`retire` 只能引用現存有效筆記的編號;同一編號重複寫只算一次;未知編號忽略並記錄。允許輸出 0 條新筆記。
- 反思用同一個模型、同一組呼叫參數;失敗**不重試**。當掉重跑時沿用已拿到的原文,**不重抽**。
- 每次反思的結果分五類公開:寫下筆記、格式對但**自己選擇不寫**、寫了但**全被拒收**、**格式壞掉**、**AI 沒回應**。

### 4.4 筆記的生命週期
- 處理順序唯一:**到期 → retire → keep → 逐條新增**;同一編號同時在 keep 與 retire → **retire 優先**;編號單調遞增、永不重用。
- 有效筆記上限 **8** 條。新增時已滿 → 先退役「**本次反思之前就有、且本次沒被 keep** 的最舊一條」;若沒有這樣的筆記 → 這條新的**不收**(記錄原因)。
- 每條筆記自建立起 **28 日曆日**到期;被 keep → 到期日重設為「當次反思日 + 28 天」;keep 不需另附依據、次數不設上限(但次數公開)。
- 每一次反思、新增、續期、退役、到期、被拒,都寫入本組帳本(append-only hash chain),含原文雜湊、成績單雜湊。
- 筆記**不得**改變任何交易規則:總曝險 ≤100、只能用候選幣、違規重試一次仍違規即維持原倉 —— 由程式照舊強制。

### 4.5 同狀態比較(**主要指標的量法**,處理期每天)
- 處理期(第 8 日起)只要有筆記的分身當天看到 **≥1 條**筆記:**6 位正式決策全部問完之後**,用該分身當天的狀態**重問兩次**同一個模型 ——
  「帶筆記」(與正式提示詞逐字相同)與「拿掉筆記」(只少筆記區塊)。兩次都照正式決策的違規重試規則;仍違規或沒拿到回覆 → 維持原倉(與正式決策同規則)。
  兩個答案都**不執行**,只記帳並公開;正式決策照常執行,與這兩次重問無關。
- **兩次的先後**逐日逐家由凍結版登記書雜湊產生的偽隨機序列決定(`ss_notes_first`,約各半)。為什麼不固定先後:後問的那次較可能碰上額度或服務狀態變化,
  固定先後會讓「呼叫失敗 → 維持原倉」系統性地落在同一邊。這個序列不是真隨機(寫登記書的人理論上能先算出來),但決定時沒有任何結果可看,挑不出對哪一邊有利的順序。
- 兩個答案都經過同一套換倉規則(爆倉當日空手、基建保護只准減倉),從**同一個換倉前狀態**出發:各扣當日換倉成本 → 持有到下一個執行日的成交價 → 扣這段期間的真實資金費。
  `c_t = (帶筆記答案的價值 − 拿掉筆記答案的價值) ÷ 換倉前淨值`,記在**決策日** t。
- 結算只用**當天真的抓到的即時價**,不用最後已知價;某一檔缺價、或假想部位持有的幣資金費不完整 → 當日 `c_t` 記「缺」(不補值)。
  逐日公開缺的原因、**缺在哪一邊**(帶筆記/拿掉筆記/兩邊)、哪些幣。
- 執行時比對:6 位正式決策拿到的候選表與系統提示雜湊必須相同,「拿掉筆記」的提示必須等於「帶筆記」的提示只少筆記區塊;任何一項不成立 → 當日 `c_t` 記「缺:輸入不一致」,不照常使用。
- 當天沒有任何有效筆記 → 沒有處理,`c_t` **定義為 0**,不多問。
- 隔天是缺失日 → 用下一個實際執行日的價格結算(兩個答案持有同樣長的時間),照實標示。
- 同一題問兩次,LLM 本來就可能給不同答案 —— 在「筆記沒作用」時這個隨機性平均為 0,只增加雜訊(附錄 E.2 的校準包含這一項)。

## 5. 期間、判定時點與統計力
- **D1** = 本登記書**凍結版**推上公開 repo、並送 OpenTimestamps 之後的第一個執行日。凍結版在附錄 B 登記**完整**的程式與執行環境:
  跑批路徑實際載入的全部第一方程式檔雜湊、Python 版本、全部第三方套件(含轉依賴)版本 —— 這份清單就是可重建環境的鎖定檔,隨登記書一起錨定。
  **D1 啟動時在乾淨子程序重算並逐項核對,多一項、少一項或任何一項不同都拒跑**(D1 只核對,不在 D1 才決定版本)。
- 計畫長度 **365 個決策日**。第 1~7 日 = **A/A 期**(兩邊都沒有筆記);**處理期** = 第 8 日起。
- **唯一一次正式檢定:第 365 個決策日結束時**。主要序列用第 **8~364** 日的決策(第 365 日的決策沒有隔日價,不列入)→ 最多 357 個觀測值。
- 判定結果在第 365 日**第一次算出時就寫進狀態檔與帳本**(含資料雜湊),之後只讀這份,不重算。
- 判定日之前:公開資料與公開頁**只放描述數字**,**不算、不公開**任何 p 值、z 值、信賴區間或「顯著」字樣。
- 若提前停止:只公開描述統計,標示「提前停止,沒有結論」;停止理由不得引用績效。
- **統計力(誠實說明,常態近似)**:t ≈ mean(C) ÷ sd(C) × √T。T = 357 時,平均每日 C 要達到約 **0.10 × sd(C)** 才有一半機會、約 **0.15 × sd(C)** 才有八成機會被看出來。
  C 在沒有筆記、或筆記沒改變決定的日子恆為 0,sd(C) 會比兩個分身的報酬差小,但**目前沒有實測值**;開跑後每天公開 C 的描述統計,讀者可以自己換算。**較小的真實差異,一年內很可能看不出來。**

## 6. 統計方法(參數在此鎖死;實作在 `shadow/learning.py::primary_stats`,底層用主實驗 `shadow/stats.py`)
### 6.1 主要指標與檢定
| 項目 | 鎖定規則 |
|---|---|
| 同狀態比較 | `c_f,t`(§4.5),f ∈ {OpenAI, Google, Anthropic} |
| **主要指標(唯一)** | `C_t = (1/3) Σ_f c_f,t`,第 8~364 日的決策、三家都有值的日子 |
| 主要檢定 | 雙尾 **HAC z 檢定**(常態近似,與程式一致);Newey–West lag = floor(4×(T/100)^(2/9));α = 0.05 |
| 輔助 | stationary bootstrap 95% 區間(L = round(T^(1/3)),circular wrapping,10,000 次,種子 20260722);**判定以 HAC 為準**,兩者不一致時並列並註明 |
| 納入規則 | 處理期全部決策日都計入,不論當天筆記數(0 條 → c = 0)、反思成敗、叫不到 AI(依規則維持原倉)、基建保護、爆倉後空手(淨值歸零後報酬記 0,與主實驗相同) |

### 6.2 閘門與三家

### 6.3 關鍵次要(判定日並列,不改主要判定;**探索性**)
- **政策層次的報酬差**:`d_f,t = r_notes(f),t − r_plain(f),t`;`D_t` = 三家平均,處理期(第 8~365 日)三家都有值的日子;公開平均、HAC p 與 bootstrap 區間。
  ⚠️ 附錄 E.1:行情有大趨勢、持倉很黏時,筆記沒作用也可能被判成有差 —— **D 的 p 值沒有校準,只供探索,不得形容為「統計上可分辨」**;兩個分身也不是隨機指派,D 不能被視為隨機化的政策比較。
- **曝險歸因**:`D_t = a + b·r_{bench_eqw_L,t} + e`(含截距、單因子、不追加因子),a 用 HAC;同時公開 b。a 不顯著只表示「扣掉曝險後未能辨別出剩下的差異」,**不推定差異的主因**。

## 附錄 E:模擬(為什麼主要指標是同狀態比較,以及正式規則的校準)
### E.1 報酬差 D 與同狀態比較 C 的誤判率(簡化模型)
虛無假設 = 筆記完全沒有作用:兩個分身用**同一個**決策規則(每天以機率 ρ 沿用昨天的淨曝險,否則在 −100%~+100% 之間重抽);
市場日報酬為常態(年化趨勢 μ、日波動 3.5%)。`D_t` = 兩個分身各走各的曝險差 × 隔日報酬;`C_t` = 從有筆記分身昨天的曝險出發、同一規則再抽一次的差 × 隔日報酬。
T = 357,每格 2,000 次,種子 20260930,用與正式判定同一支 HAC z(α = 0.05,雙尾)。重跑:`python tools/learning_type1_sim.py 2000`。

| 年化趨勢 μ | 持倉沿用機率 ρ | 報酬差 D 誤判率 | 同狀態 C 誤判率 |
|---|---|---|---|
| 0% | 0.90 | 5.3% | 5.9% |
| 0% | 0.99 | 5.1% | 2.7% |
| +80% | 0.98 | 9.6% | 4.0% |
| +150% | 0.99 | 23.5% | 1.7% |
| −60% | 0.99 | 8.0% | 2.1% |

讀法:誤判率應該接近 5%(每格 2,000 次的抽樣誤差約 ±1 個百分點)。行情有明顯趨勢、兩個分身的持倉又很黏時,D 會因為「兩邊剛好一個多一個空、而且一直不換」被當成有差;
C 每天都從同一個起點比,不受這種路徑影響。這張表只用來說明選 C 的理由,**不是**正式規則的校準(見 E.2)。

### E.2 正式判定規則的虛無校準(事先寫死通過標準)
用 §6.1 的**正式規則**(三家都有值的日子取平均、HAC z、缺值不列):三家共用同一條市場報酬(共同衝擊)、GARCH 波動、
平均每段 60 天的多空趨勢(長期相依)、AI 決定 = 雜訊很大的趨勢追隨並以機率 ρ 沿用昨天部位、每家每天「帶筆記/拿掉筆記」兩次重問(虛無 = 同一規則)、
呼叫失敗 → 維持原倉、換倉成本 7bps × 換手、85% 的家族日有筆記。T = 357,每格 2,000 次,種子 20260930。
**通過標準在跑之前寫死在程式裡**:誤判率 ≤ 7%、HAC 95% 區間涵蓋真實平均的比例 ≥ 93%(真實效果每天 +0.04%、有筆記的比例 85% → 真值 0.034%);
